# Feature Dictionary & Data Specifications

This document defines the 15 production features generated by `FeaturePipeline` and `AccountState`.

---

## 🟢 1. Monetary Features

### `amount`
- **Data Type**: `float64`
- **Unit**: Currency units (USD equivalent)
- **Description**: Raw transaction amount paid by the sender account.
- **Statefulness**: Raw transaction attribute.

### `spending_deviation_score`
- **Data Type**: `float64`
- **Formula**:
  $$\text{Z-Score} = \frac{x - \mu}{\max(\sigma, 1.0)}$$
  where $\mu$ is the historical mean amount and $\sigma$ is the historical standard deviation computed via **Welford's Algorithm**.
- **Description**: Standardized deviation of the current transaction amount relative to the sender account's prior spending profile.
- **Statefulness**: Stateful. Evaluated using only past transactions. Zero variance fallback ($\sigma < 1.0$) defaults to $\sigma = 1.0$. If transaction count $< 2$, returns $0.0$. Returns $0.0$ also when current amount equals historical spending mean.

## ⏰ 2. Temporal Features

### `hour`
- **Data Type**: `int64` (Range: 0–23)
- **Description**: The hour of the day extracted from transaction timestamp.

### `day_of_week`
- **Data Type**: `int64` (Range: 0–6, where 0 = Monday, 6 = Sunday)
- **Description**: Day of the week of transaction execution.

### `month`
- **Data Type**: `int64` (Range: 1–12)
- **Description**: Calendar month of transaction execution.

### `is_weekend`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Indicator for transactions occurring on Saturday or Sunday (`day_of_week >= 5`).

### `time_since_last_transaction`
- **Data Type**: `float64` (Unit: Seconds)
- **Description**: Elapsed time in seconds since the sender account's immediately preceding transaction.
- **Statefulness**: Stateful (`AccountState.last_timestamp`). Returns `0.0` for the first observed transaction of an account. Strictly non-negative ($\ge 0.0$).

### `velocity_score`
- **Data Type**: `int64` (Minimum: 0)
- **Description**: Lifetime cumulative count of prior transactions processed for this sender account prior to current event.
- **Statefulness**: Stateful (`AccountState.transaction_count`). Note: This is an integer transaction count (not a rolling-window rate).

### `is_first_transaction`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Flag indicating if this transaction is the first transaction recorded for the sender account (`velocity_score == 0`).

---

## 🔗 3. Relationship Features

### `is_new_receiver`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Flag indicating if the beneficiary account (`Account.1`) has never been transferred to previously by this sender (`receiver not in state.known_receivers`).

### `is_new_bank`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Flag indicating if the target bank ID (`To Bank`) is new for this sender account.

### `is_new_payment_format`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Flag indicating if the payment format/channel is being used for the first time by this sender.

### `is_cross_bank_transfer`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Indicator for inter-bank transfers (`From Bank != To Bank`).

### `is_cross_currency_transfer`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Indicator for foreign exchange transactions (`Payment Currency != Receiving Currency`).

---

## 💳 4. Transaction Features

### `payment_channel`
- **Data Type**: `string` / Categorical
- **Description**: Payment method format specified in transaction record (ACH, Wire, Credit Card, Cheque, Cash, Bitcoin, Reinvestment).

---

## 🎯 5. Target Label

### `is_fraud`
- **Data Type**: `int64` (Enum: 0, 1)
- **Description**: Ground truth target label derived from IBM AML synthetic laundering annotations (`Is Laundering`).
  - `1`: Money laundering / fraudulent transaction.
  - `0`: Legitimate banking transaction.
